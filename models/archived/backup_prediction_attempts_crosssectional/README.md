# 横截面预测尝试（备份）

## 📋 概述

本文件夹包含早期的**横截面预测**尝试。这些方法不依赖时间序列的连续性，而是利用空间特征、多指标关系等进行预测。

## ✅ 为什么横截面预测更合适？

与时间序列模型相比，横截面预测方法：
- ✅ **不依赖时间序列连续性**（适合不规则采样数据）
- ✅ **利用空间特征**（经纬度、省份、城市）
- ✅ **利用多指标相关性**（pH、温度、溶解氧等）
- ✅ **适合事件驱动采样**的数据特性

## 📁 文件列表

### 1. baseline_prediction.py（基线模型）
```python
方法：历史均值法
用途：作为基线参考
效果：R² ≈ 0（预期）
状态：参考基准
```
- **说明**：最简单的预测方法，使用历史平均值作为预测
- **用途**：评估其他模型是否优于简单均值
- **结论**：当R² < 0时，说明模型比均值还差

### 2. crosssectional_prediction.py（多指标预测）
```python
方法：使用其他水质指标互相预测
特征：pH, 温度, 溶解氧, 浊度等
模型：Random Forest, Linear Regression
效果：R² < 0 ~ 0.15
状态：效果不理想
```
- **问题**：指标间相关性较低（< 0.1）
- **原因**：数据采样不规则，破坏了指标间的物理化学关系
- **教训**：需要更多的特征工程

### 3. improved_province_prediction.py（改进的省份预测）
```python
方法：按省份分组，多模型集成
模型：RandomForest, GradientBoosting, Ridge
特征：省份、城市、历史统计值
效果：R² ≈ 0.15 ~ 0.25
状态：有一定效果但不理想
```
- **改进**：增加了省份、城市等分类特征
- **问题**：数据量少，特征工程不足
- **结论**：省份级别的聚合有帮助，但需要更多特征

### 4. station_based_prediction.py（监测站预测）
```python
方法：按监测站分组，添加滞后特征
特征：历史滞后值（lag 1, 2, 3）
模型：Random Forest
效果：R² ≈ 0.20 ~ 0.30
状态：效果中等
```
- **优势**：考虑了监测站的独立性
- **问题**：数据采样稀疏，滞后特征效果有限
- **结论**：监测站级别建模有意义，但需要更多样本

### 5. gtwr_prediction_by_province.py（地理时间加权回归）
```python
方法：GTWR（地理和时间加权回归）
特征：经纬度、时间、空间权重
效果：R² ≈ 0.15 ~ 0.25
状态：复杂但效果一般
```
- **理论**：考虑空间和时间的局部异质性
- **问题**：经纬度数据可能不准确，时间不规则
- **结论**：理论先进但数据质量限制了效果

### 6. final_cleaned_prediction.py（严格清洗后的预测）
```python
方法：严格数据清洗 + 多模型
清洗：去除异常值、缺失值、不合理值
效果：R² < 0 ~ 0.10
状态：清洗后效果反而变差
```
- **清洗规则**：
  - 水温：0-40°C
  - pH：0-14
  - 溶解氧：0-20 mg/L
- **问题**：清洗后数据量减少，指标关系仍然弱
- **教训**：过度清洗可能损失信息

## 🎯 问题分析

### 1. 数据质量问题
- **异常值多**：水温-61°C、pH 199等不合理值
- **相关性低**：指标间相关系数 < 0.1（理论上应该>0.3）
- **缺失值多**：部分监测站数据不全

### 2. 采样问题
- **时间不规则**：0-222天的巨大间隔差异
- **事件驱动**：更像"发现污染才检测"而非定期监测
- **站点混合**：不同站点数据混合，破坏了时空连续性

### 3. 特征工程不足
- **空间特征**：只有省份、城市，缺少更细致的地理信息
- **时间特征**：只有日期，缺少季节、趋势等
- **交互特征**：缺少指标间的交互项

## ✅ 成功经验

### 1. 空间特征有效
- 省份、城市等分类特征有一定预测能力
- 经纬度在合理范围内时也有帮助

### 2. 监测站独立建模
- 每个监测站独立建模比全局建模效果好
- 证明了不同站点的数据差异大

### 3. 多模型集成
- Random Forest 通常优于线性模型
- Gradient Boosting 在部分情况下效果最好

## ❌ 失败教训

### 1. 过度清洗适得其反
- `final_cleaned_prediction.py` 清洗后效果反而变差
- 原因：样本量减少，丢失有用信息

### 2. 复杂模型不一定好
- GTWR 理论先进但效果不如Random Forest
- 原因：数据质量限制了复杂模型的发挥

### 3. 单一特征效果有限
- 只用水质指标互相预测效果差
- 需要结合空间、时间、历史统计等多种特征

## 🚀 改进方向

### 1. 增强特征工程
```python
# 空间特征
- 经纬度 + 距离最近城市的距离
- 省份 + 城市 + 区县
- 地形特征（海拔、地貌）

# 时间特征
- 年、月、季节、星期
- 是否节假日
- 距离上次采样的天数

# 历史统计特征
- 过去7/30/90天的均值、标准差、最大值、最小值
- 移动平均
- 指数平滑

# 交互特征
- pH × 温度
- 溶解氧 × 温度
- 经度 × 纬度
```

### 2. 数据增强
```python
# 插值填充
- 时间插值（填补大段空白期）
- 空间插值（利用相邻站点）

# 特征衍生
- 从现有指标计算新指标
- 组合多个指标的比值

# 外部数据
- 气象数据（降雨、气温）
- 人口密度、工业分布
- 河流水系信息
```

### 3. 更好的建模策略
```python
# 分层建模
1. 省份级别：粗粒度预测
2. 城市级别：中等粒度
3. 监测站级别：精细预测

# 多任务学习
- 同时预测多个指标
- 利用指标间的相关性

# 迁移学习
- 数据多的站点 → 数据少的站点
- 利用站点间的相似性
```

## 📚 推荐的下一步

### 对于时间序列预测
- ❌ 不推荐：ARIMA、LSTM等严格的时间序列模型
- ✅ 推荐：使用 `timeseries_models_province/` 或 `timeseries_models_station/`
- 原因：虽然效果仍然差(R²<0)，但已经是最好的时间序列尝试

### 对于横截面预测
1. **baseline_prediction.py**
   - 作为基准，评估其他模型

2. **station_based_prediction.py**（最推荐）
   - 监测站独立建模
   - 加入更多特征工程
   - 有一定效果（R² 0.2-0.3）

3. **improved_province_prediction.py**
   - 省份级别预测
   - 适合宏观趋势分析

### 对于新的尝试
- 重点：**特征工程** > 模型选择
- 方向：空间特征 + 历史统计 + 多指标组合
- 工具：XGBoost、LightGBM（比Random Forest更强大）

   ```

   ```

   ```

   - 良好模型：R² ≈ 0.4-0.5（需大量特征工程）

   ```
